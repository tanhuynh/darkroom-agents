# A scripted write drops the AI-Sky bitmap from Camera Raw's cache (the other AI/object masks survive); only the dialog's yellow AI icon brings it back, and `batchPlay` cannot write `$BigT`
- **Agent:** claude
- **Target:** engine.md §6 *Write semantics* (the bullet "Every scripted write reads back without `$BigT` until the user's Update … some AI masks render only partly before it"), §9 (who does what); WORKFLOW §2.7/§3; **narrows/amends** the merged 0367 rule and **amends** `2026-11-20-claude-9884-ai-mask-refresh-not-needed.md` (merge the two together; do not keep both)
- **Type:** contradiction (narrows 0367 and 9884) + engine fact
- **Rule:** IF a scripted `set` writes a filter that contains an **AI Sky** correction (Select Sky, `MaskSubType 2`) → DO render after the write and compare the sky region with the previous render: if the Sky correction's own effect is gone (the region equals the zero-slider control; here sky ΔL\* +6.35, grey-cloud a\* back to the control) → ask the user for the dialog Update (**double-click Camera Raw Filter → click the yellow AI icon → OK**; **OK alone does not help**) and re-render before judging anything else. Batch all changes of a pass into one write, make Sky edits last or by hand in the dialog, and use a parametric sky (gradient ∩ Luminance − Mountains) when the sky has to be scripted.
  - **A missing `$BigT` in the read right after a write is not the signal:** it is absent after every write (0, 5 and ~35 s) and a later read can have it back; the Sky bitmap can be missing from a `$BigT` that is present (see below).
  - Object masks (with paint gestures), AI Mountains, Select Subject and clones that share a digest **kept rendering through every scripted write** in this case.
  → CHECK for each write: the region of every AI-mask correction against the prior render; an unchanged sky is the symptom.
- **Evidence:** case 0834 (Camera Raw 19.0; masks made by the user in the dialog):
  - **Healthy → broken:** probe, revert and pass-1 writes with Sky, Subject and Mountains kept the Sky rendering with no Update. After the user added three Object masks and a clone, **every** scripted write dropped the Sky correction — one adding a clone correction, and two slider-only edits (Strata calm Exposure, then Sky Tint 0.10 → 0.11 on a fresh Save-As duplicate). Mountains, Subject, trees unchanged each time (rock ΔL\* +0.08, base −0.05).
  - **Container:** `$BigT` is `ACR\0` + version + count + a 32-byte index per bitmap (digest, size, offset), sorted by digest. Healthy: 6 entries, 443,824 B (Object 1, Object 2, Mountains, **Sky ≈ 315 KB**, Subject, Object 3). After a slider write then the dialog's **OK only**: **5 entries, 128,808 B, the Sky entry missing**; the sky stayed broken (render identical to the broken one: sky L\* 52.51, a\* 0.64). After the yellow-icon click + OK: `$BigT` back at 443,824 B with the **same SHA-1 as the healthy reference** — the Select Sky model gives the same bitmap each time.
  - **Alchemist listener (Update click → OK):** one event, a `set` on `filterFX` `_index 1` with `dialogOptions: "dontDisplay"` and keys `$CrVe, $PrVN, $PrVe, $LCs, $BigT` (Alchemist prints `$BigT: {}`: binary, "not re-playable"). The dialog's `$LCs` equals ours after whitespace normalisation (393 attributes, 0 differences). So the Update adds nothing but `$BigT`.
  - **Round trip from inside Photoshop (UXP console, no connector change):** `get` returns `$BigT` as `[object ArrayBuffer]`, 443,824 B; `set` with that same ArrayBuffer fails — **"Illegal data type. ByteArray is not supported for this operation"** (same text as 0367). The filter was unchanged after the failure. Patching the plugin to convert `{type:"Buffer"}` to binary would therefore not help.
- **Conflicts with:** engine §6 (0367: "reads back without `$BigT` until Update; some AI masks render only partly before it" — here `$BigT` presence is not the criterion and the Sky correction vanishes entirely); 9884 (masks rendered after scripted writes with `$BigT` missing — true for Mountains/Subject/Object here, false for the AI Sky). 9751 (People parts) and 0159 (AI-Sky edge speckle, a cancelled Denoise visit leaving the AI Sky un-rendered) fit the AI-Sky side.
- **Not tested / hypotheses:** why the Sky entry is evicted while the others stay (the Sky is the largest bitmap, and `EdgeShift 0.3` makes it a refined mask; both unverified); whether a Sky written without `MaskDigest` is recomputed headless (untried); computer-use clicking of the icon (untried). A passive Sky-only filter (3 masks) survived writes earlier in the same case, so the loss may need a second mask type present.
- **Scope:** seen on 1 case (0834), one session, Camera Raw 19.0 / Photoshop Beta; 9884 and 0159 point the same way.
