# `$BigT` cannot be written back, so brushes stored there (`MaskBrushTable`) never survive a scripted write; `ps_filter.js set` now refuses while one exists
- **Agent:** claude
- **Target:** engine.md §5 (`$BigT`) and §6 *Write semantics* (Brush); WORKFLOW §3 ("standalone brush last"); confirms the hypothesis in `2026-11-20-claude-9944-brush-last-empty-intersect.md`
- **Type:** change rule (adds a hard limit and a tool guard)
- **Rule:** IF `$LCs` contains a brush whose bytes live in `$BigT` (`crs:MaskBrushTable="…"`, `MaskBrushUncompressedBytes`) → DO NOT run a scripted `set`: the write must omit `$BigT` (batchPlay rejects it), and the brush is then lost at the next dialog session. Instead: paint such brushes **after the last scripted write**, or replace them with an XMP-native mask (linear/radial gradient, luminance/color range, object mask) before scripting. Brushes whose dabs are inline in `$LCs` (`Mask/Paint` under the correction) survive. `tools/ps_filter.js set` enforces this: exit 4 naming the brush, `--allow-brush-loss` to accept repainting. → CHECK before a scripted pass: `node tools/ps_filter.js set … --dry` shows no REFUSED line.
- **Evidence:** case 0367, doc 142, corrections Vegetation (objects + brush add, dabs inline) and Mountains (AI Mountains − Brush 1, `MaskBrushTable="2200530C…"`, 7559 bytes):
  - 2026-11-22: write with `$BigT` omitted → read-back without `$BigT` (was 1,178,062 chars as JSON = 409,464 bytes), XML identical. After the user's dialog Update + OK: `$BigT` back at 1,165,051 chars (−13,011), Vegetation brush intact, **Mountains subtract brush empty** (no `MaskBrushTable`) → the subtract excluded nothing. Restored via History (state before the write); read-back matched `measure/0367_lcs_before.xml`.
  - 2026-11-23: identity write resending `$BigT` as binary (Buffer → socket.io attachment → ArrayBuffer) → `Error: Illegal data type. ByteArray is not supported for this operation`; nothing applied. So the omission in `ps_filter.js` is forced, not a choice.
  - Matches 0044 and 9944 (brushes lost at the next dialog session after a write).
- **Open:** what makes Camera Raw store a brush as a table instead of inline dabs (standalone Brush component vs refinement inside an object/AI mask? stroke count?). Worth one controlled test: paint the same stroke as a standalone Brush and as an object-mask refinement, read `$LCs`.
- **Also changed:** adb-mcp `executeBatchPlayCommand` records each batch as one named History step (`historyName`, default "AI batchPlay"; `ps_filter.js --history`), rolled back on error. `ps_filter.js`, `apply_filter.js` and `get_filter.js` accept the list response adb-mcp now returns.
