# After a scripted filter write, AI-mask (Subject / People-part) corrections stop rendering until the user refreshes them in the Camera Raw dialog (yellow AI edit status icon)
- **Agent:** claude
- **Target:** engine.md §6 *Write semantics* (first bullet: "AI masks … survive a write that omits their bitmap data") and §9 (who does what); WORKFLOW §3 (AI-mask reuse rule); amends the pending `2026-11-17-claude-0025-cloned-ai-mask.md`
- **Type:** engine fact (DURABLE: Camera Raw behavior; the `$BigT` observation is ACCESS: adb-mcp)
- **Rule:** IF a scripted `set` of the Camera Raw Filter changes corrections that use Subject / People-part AI masks (the XML round-trips unchanged) → the masks **do not render** after the write, and `$BigT` is missing from the next `get` → DO ask the user to **open Filter › Camera Raw Filter, check whether the AI edit status icon is yellow, click it to refresh if so, then press OK to save the update (Cancel if nothing changed)** — one manual refresh per scripted pass → the same XML then renders, `$BigT` is back, mask digests unchanged. Never judge a scripted AI-mask value from a render taken before that refresh.
  → CHECK before trusting a pass: read the filter (`$BigT` present, ~1.1 MB for 14 masks) and diff against the previous render; a mask that "does nothing" with ΔL\* exactly 0.00 inside its region is the symptom, not evidence the mask is empty.
- **Evidence:** case 9751 (portrait at Bryce, 14 AI masks: Subject, Sky ×2, 8 People parts, Natural Ground, Vegetation, Mountains; Camera Raw 19.0; 2000 px diffs vs a control render of the cropped, unchanged state):
  - After a scripted write (probe `LocalExposure2012` ±0.5 stored): Sky −38 L\*, Natural Ground/Mountains +25…+50 L\* rendered; **Subject 1, Clothes, Hair showed ΔL\* 0.00** on jacket/face/hair; Facial Skin and Vegetation behaved differently between two probes (Vegetation 0 in one, −12 in another) — the effective set changed with the state.
  - The readback XML equalled the sent XML byte for byte and the digests were identical, so the write was not the problem; rendering twice gave identical numbers (not timing).
  - Sending the saved `$BigT` (1.1 MB string from the earlier `get`) with the write changed nothing (to the digit) — it does not round-trip through the connector, so "omit it, it is cached" is not enough on its own.
  - The user set Subject Exposure to +1.00 in the dialog (stored 0.25 — confirms the 4× rule) and pressed OK: jacket +19, face +16, hair +18 L\*, nothing outside the person → the Subject mask is good. My next scripted write (Clothes +0.5, Hair +0.5, Vegetation −0.5, Subject 0.25 kept in the XML) made the Subject effect vanish again. After the user opened the dialog and pressed OK: jacket +43 (Subject +19, Clothes +24), hair +44, pines −12, Subject effect back.
  - Restoring the original XML (with the same refresh rule noted) read back identical and rendered at ΔL\* 0.00 vs the control.
  - **Correction (resolved):** a later "not reproducible" result (canyon −4.5 → −0.85 L\*, face +3.1 → +6.7 between two renders of the same `$LCs`) was **not** an AI-mask effect. The user's dialog session had also set global **HSL Luminance** (`$LA_R` +8, `$LA_O` +23, `$LA_Y` +13, `$LA_G` +1) — separate filter keys outside `$LCs` — which lifts orange rock and skin; `ps_filter.js set` resends every key, so they persisted. I had diffed only `$LCs` and printed only `$LCs`/`$BigT`, so the change was invisible. Lesson: diff **every** filter key (and list them all) between reads before attributing a render change to masks. The refresh finding above (probes with `$BigT` absent, before any HSL change) stands.
- **Conflicts with:** engine.md §6 "AI masks … survive a write that omits `$BigT` (verified 9956: patch ΔL\* 0.00)" and the pending cloned-ai-mask proposal ("masks still evaluated on every later render", 0025). Both may have been true because a dialog OK happened between rounds (0025: the user's Remove + OK; 9956: Remove) or because a single mask is rebuilt from its reference point — not established. Narrow the rule to "survive in the XML; render only after a dialog OK" rather than keeping two conflicting rules.
- **Not verified:** whether the refresh is needed after *every* write or only the first; whether landscape masks (Sky, Ground, Mountains) always render without it (they did in two probes, Vegetation did in one of two); whether a single-mask filter (0025) behaves differently.
- **Scope:** seen on 1 case (9751), one session, Camera Raw 19.0 / Photoshop Beta.
