- **What worked:**
  - Cropping first, then the critique, then the masks — the critique named the masks (Subject, Sky, Facial Skin…) before the user made them.
  - **Sky − Subject** protected the windblown hair against the cloud (no halo at 1:1).
  - Skin: a plain Exposure lift **whitened** it (+0.05 → cheek L\* +9, C\* −5); Exp 0 + Highlights −0.15 + Sat +0.06 kept the hue (~56°) and most of the chroma.
  - The 1:1 check (a hard-cropped 1884×1762 copy of face and hair) was clean: hair wisps against cloud and canyon, teeth not clipped, eyes natural, skin texture kept.
  - Measuring the Camera Raw mask itself: a Subject +0.25 render minus the control gave the alpha for `measure_all.py --mask` (first real-image check of that option).
- **What went wrong / tool lessons:**
  - A **scripted filter write leaves the AI-mask corrections un-rendered** (`$BigT` disappears from the next read) until the user opens the dialog, clicks the yellow AI edit status icon and presses OK. My first probes read "ΔL\* 0.00 inside the mask" as if the masks were empty (inbox `2026-11-19-claude-9751-ai-mask-refresh.md`).
  - I told the user a render change was "not a function of the XML" and blamed the masks, when the user's dialog edit had also set global HSL Luminance outside `$LCs`. I had diffed only `$LCs` and printed only `$LCs`/`$BigT`. **Diff every filter key.**
  - The Sky forecast (−3…−4 L\*) used a rule written for a ramp ∩ bright range; the whole-sky mask gave −8.5…−11 (−5…−7 at Highlights −0.10). Check that a rule's mask matches before forecasting.
  - My first "scarf" and "jacket" sample boxes were in the wrong frame (cropped vs uncropped coordinates).
  - A Photoshop crash lost the first mask attempt (new document id; recovery brought back neither the crop nor a filter): re-read the state, redo the crop, keep the render and numbers.
  - Opening the CR3 with Open Image gave a flattened pixel layer with no raw SO; Open Object gave the Smart Object.
