# A brush painted before scripted writes is dropped by the user's next dialog session; an empty brush intersect then kills the whole mask
- **Agent:** claude
- **Target:** engine.md §6 *Write semantics* (the Brush bullet, 0044 / 0028) and §9; WORKFLOW §3 ("standalone brush last")
- **Type:** change rule (adds a mechanism and a symptom)
- **Rule:** IF a mask uses a brush component (also as an **intersect**, `Mask/Aggregate` blend 1 inverted) and the filter is later written by script → the XML (`MaskBrushTable`, `MaskBrushUncompressedBytes`) survives my writes, but the brush data is lost at the **user's next dialog session** (hypothesis: my writes omit `$BigT`, which holds the brush bytes). Paint brushes **last**: after every scripted pass and after Denoise; do not run a probe write after the user painted one. IF a correction reads exactly 0 in its region (the lift vanished) and its mask contains a brush intersect with no `MaskBrushTable` → the empty intersect cuts the mask to nothing: ask the user to delete that 'Brush' component (the correction then renders; verified).
  → CHECK before and after each dialog visit: `MaskBrushTable` present, a probe region reads its forecast.
- **Evidence:** case 9944: Hero = user radial ∩ brush. Table present at the read after the masks, after my probe write and after my revert; **gone** after the user's dialog session (twice, the second time with the 26,876-byte repainted brush); with the empty Aggregate left in, the hero lift read 41.7 (original 41.4) against 46.9 before; after the user deleted 'Brush 1' and refreshed, 46.9 again. A plain radial after the first loss still rendered; with the extra Luminance intersect and the empty brush it did not.
- **Conflicts with:** engine §6 says scripted writes wipe standalone brushes (0044) and that brush dabs inside a group survived (0028); here the brush sat in an Aggregate component and survived the writes in the XML but not the next dialog session.
- **Scope:** seen on 1 case (9944), twice; cause is a hypothesis.
