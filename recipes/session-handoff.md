## Workflow (user rules in bold; canonical text in `WORKFLOW.md` §2)
0. **Classify + load** (README "In a session").
1. `get_documents` / `get_layers` / doc info (size, raw SO type), baseline render.
2. **WB check first, before any edit** (`measure_all.py baseline`; `wb.py` for detail). Global cast → user fixes in the raw SO.
3. Composition / crop: weight map + crop mocks; non-destructive `crop` (`delete:false`); commit the crop before the user opens the filter dialog.
4. **Critique says what works** (composition, leading lines, DR, shadow detail, tonal balance) + top 2–3 FIX/TASTE, and names the AI masks each fix needs. Ignore the mat; small clipping only matters for print.
5. **AI masks (user step):** the user makes the masks the critique asked for (Select Subject; people parts; Sky / Landscape only if present). Agent reads, quality-gates (1:1 overlay), clones them; poor/missing → parametric fallback. Optional `measure_all.py --mask` alpha (PS proxy).
6. **Plan all edits in text (stored + dialog values, mask source per correction), wait for approval, then apply as one batched call**; render → `measure_all.py diff` → adjust in follow-up passes.
7. **Before every scripted write: read the live filter and resend ALL keys** (`$GLW*`, `$Rtch`, …); omit `$BigT`.
8. **Remove: user paints it in a Camera Raw Filter, never in the raw SO dialog.** Save before the first scripted write after a Remove. Standalone brush work last.
9. After the user saves: archive step (`recipes/README.md`) — case JSON + card + index row; rule changes go to `recipes/inbox/` as proposals.
10. **Cleanup:** delete render PNGs and `<id>-state.md` in `measure/` (keep the folder). Commit in `darkroom-agents` (git details per adapter); the user pushes.
11. **Context checkpoints** (end of image, after 3+ renders, phase change): write `measure/<id>-state.md`, then the user runs clear/compact (WORKFLOW §2 step 9).

## Local model — PAUSED (Nov 19 2026; decision: not practical on this machine)
Experiment: Qwen3.8-27B-MLX-4bit in Bionic on an M4 Max Studio, 36 GB, benchmark 0025. Setup is kept and reusable: `agents/local-qwen38-27b/` (adapter, `START.md`, `render-recipe.md`, `bionic-mcp.json`), `docs/local-model-setup.md`, `tools/darkroom_mcp.py`.
- **What worked:** `darkroom` file access, the render recipe (2000 px ProPhoto PNG → `prophoto_to_srgb` → `measure_baseline`), correct write-policy recital, correct classification (wildlife, crane in grass) and a sound WB read once the chat was short.
- **What failed:** Metal `OutOfMemory` and multi-minute prefill at AutoFit's 107k context (84k-token prompt, no cache hit); Bionic ignores Local Model Defaults (fix: `lms load --context-length 32768`); fixed overhead ~6.8k tokens; at 32k the window filled (32.3k) before the critique was shown, so work needed a new chat per stage and re-reading ~8k of docs each time; skipped the profile gate, read both playbooks, skipped crop/subject/AI-mask steps, overstated WB confidence, mis-named the species earlier.
- **Conclusion:** the limit is capability under a growing playbook plus context cost, not only memory. Claude and Gemini do the same workflow faster and more reliably; stepwise supervision of a local model costs more than editing in Photoshop by hand.
- **If revisited:** a 64 GB Mac (M5 Max-class) removes the memory limit but not the instruction-following gap — first test an open ~70B model through a hosted API on the same 0025 task (gates, classification, plan) before buying hardware. Per-image `measure/<id>-state.md` is now built as the checkpoint file (WORKFLOW §2 step 9); slice reads (`RESUME.md`) are still an idea.
- Lessons that apply to every agent were moved into `WORKFLOW.md`/adapters (one playbook unless the landscape is itself a subject; same §2 order for all agents; gates).
